## Reproduced checks

The following commands were run serially from the module root:

```text
moon fmt --check
moon check --target all --deny-warn --warn-list +73
moon build --target all --deny-warn --warn-list +73
moon test --target all --no-parallelize --deny-warn --warn-list +73
moon info --target all
moon package --list
moon bench --build-only --target native --deny-warn --warn-list +73
moon coverage analyze -- -f cobertura -o coverage.xml
bash scripts/interoperability.sh
```

The test matrix was Wasm `284/284`, Wasm-GC `221/221`, JS `284/284`, and
Native `298/298`. The socket script covered the local HTTP/1.1 smoke server,
HTTP/2 prior knowledge, and h2c upgrade. It did not cover independent HTTP/3
or TLS interoperability.

The historical shell script made wget and nghttp optional. Its final success
line alone therefore cannot prove that those clients ran; retain individual
client logs when using the baseline as evidence. The v1 replacement is
`tools/interoperability.mbtx`, which requires all three clients and records
each of its six cases separately. The old shell script was removed after
equivalent real-socket checks passed with the replacement.

Live CLI verification on 2026-09-29 confirmed that `moon coverage analyze`
means **run tests with instrumentation and report coverage** for Moon
`0.1.20260920`; it is not a report-only read of historical data. CI now runs
`moon coverage clean` first to remove residual coverage artifacts. The
historical benchmark command above used `--build-only`, so it proves only
that benchmarks compiled. `tools/benchmarks.mbtx` executes Native release
benchmarks and records raw output; a controlled baseline comparison and
accepted performance thresholds remain separate, open gates.

`moon package --list` currently includes local documentation and therefore is
not a clean release build while the untracked handoff file exists. The package
must be regenerated after source freeze and checked against the final Git
revision before publication.

`tools/release_evidence.mbtx --check-clean` has been run against the v1
development worktree and correctly refused tracked edits and untracked
files before packaging. A future clean run verifies every archive member
against its committed Git blob and records SHA-256, sizes, file list,
toolchain and resolved dependencies. Its successful package check does not
approve a production release. This tool has not produced a release package
from the current dirty worktree.

## Known gaps carried into v1

- QUIC TLS 1.3 CRYPTO/traffic-secret integration and key update.
- QUIC path migration driver actions and packet-space frame legality.
- HTTP/3 CONNECT settings and authority-form enforcement.
- Explicit resolver and policy enforcement for every Native network entry.
- Native TLS credentials, trust anchors, server handshakes, and `h3` ALPN.
- Independent HTTP/3 interoperability, certificate-negative tests, long-run
  pressure, repeatable performance thresholds, and a current security scan.
