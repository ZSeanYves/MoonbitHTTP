# Contributing

> Status: canonical
> Scope: repository changes to the 0.7.0 development line
> Source: working-tree (governed by Git)
> Last reviewed: 2026-10-01

Keep each change inside the package boundary that owns its behavior. New
protocol parsing belongs in a codec or state transition; connection and I/O
capabilities belong in `transport`; client and server packages choose policy
and lifecycle. Optional policy modules must not import protocol drivers.

Every new public type or function needs a package README entry and a focused
test at the smallest useful layer. Prefer explicit capability parameters over
hidden globals. Preserve error stage, endpoint and stream context when
converting an underlying failure into a public error.

Run these checks serially from a clean checkout before opening a change:

```sh
moon fmt --check
moon check --target all --deny-warn --warn-list +73
moon test --target all
moon run tools/check_architecture.mbtx
moon run tools/check_distribution.mbtx
git diff --check
```

The distribution checker is an allowlist, not a suggestion. If a new source,
fixture or document should ship, classify it in `tools/distribution.json` and
update [Distribution contents](../release/packaging.md) in the same change.
Generated interfaces and dependency graphs are regenerated by tools; do not
edit them by hand.
